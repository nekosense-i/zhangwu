# 账务 · Ledger

视觉优先的私人财务分析工作台。纯静态部署、无第三方脚本、无后台服务。

## 隐私设计

此仓库是公开的，但**不包含明文财务记录，也不包含解锁密码**。完整的 2025.11—2026.11 账务明细以 AES-256-GCM 加密后储存在 `data.vault`。浏览器通过 Web Crypto API 进行 PBKDF2-SHA256（250,000 次）密钥派生和本机解密；数据不会在解锁时上传任何服务器。GitHub / Pages 可以下载加密文件，但没有独立密钥无法查看内容。

打开页面后需要输入单独提供的高强度解锁密钥。请妥善保存密钥；遗失后无法由仓库恢复。不要把密码提交到仓库，不要把浏览器页面设置成自动解锁。站点使用的同源 localStorage 也只缓存加密后的更新副本。

## 能做什么

- 财务总览、12+1 月收支走势图、分类环图、商户与渠道排行、逐日消费热力图
- 月度与渠道筛选、图表点击钻取、交易搜索、信用卡分期与账单对比、待核对交易列表
- 本地添加交易、调整已有交易分类、手动确认待核支出
- 点击顶部下载按钮导出个人更新后的 `.vault` 加密备份
- 响应式布局：手机底部导航、桌面侧边栏

## 核算口径

识别消费为此前四渠道合并、匹配去重、扣减退款后的结果；信用卡还款、理财申赎和分期本金不直接并入当期消费。代发工资只统计银行流水中明确标记的工资。**工资减去识别消费并不等于净储蓄**，存在转账性质不明、金融扣款待核、未上传的其他账户和未出账交易等缺口。首尾两个月为不完整样本。

## 本地开发

静态网页无构建依赖，在仓库目录执行 `python3 -m http.server 8080`，然后访问 `http://localhost:8080`。也可把 `index.html`、`styles.css`、`app.js`、`favicon.svg` 和 `data.vault` 一并保留在本地，使用静态 HTTP 服务器运行。

## 部署

推送到 `main` 后，仓库内的 GitHub Actions 工作流会将根目录部署到 GitHub Pages。必要时在仓库设置 `Settings → Pages → Build and deployment → Source: GitHub Actions` 启用。注意：任何能打开网站的人都能获取**加密**数据文件；保密性依赖独立密钥强度，网站本身并不使用账号登录。
